Bounded worker research for [#254](https://git.accad.pro/murzintsevav/nfsu-switch/issues/254),
on main `6e65e30e43b1393ee5e32d5a075c86778e45603c`. No renderer, race state,

## Inputs and reproduction

`tools/hud254_trace.py` requires Python 3.8+ and Capstone 5.0.7. `--native`
also requires Unicorn 2.1.4. Reports go to a fresh ASCII-named directory outside
both input trees. Before/after manifests include every directory's mtime and
every file's size, mtime and SHA-256. The game is never launched. Retail and
reference files remain read-only. Extracted/derived assets stay outside Git.

From the original repository root, preserve the reference path before entering
the detached worktree:

```powershell
$hud254Reference = Join-Path (Split-Path (Get-Location).Path -Parent) 'reference'
Set-Location 'build-worktrees/254-codex-worker'
$hud254Source = git rev-parse HEAD
python -B tools/hud254_trace.py --root 'E:/Games/nfs/Need For Speed - Underground/Need For Speed Underground' --reference $hud254Reference --source $hud254Source --native --out out/254-evidence
python -B tools/hud254_trace_test.py --report out/254-evidence
```

The tool accepts only `speed.exe` SHA-256
`C0FAD450912952F53809A54690D235AA8B4E25B9F46650693C7CBEE1B4C074B7`.
It maps virtual addresses through bounded PE32 sections. `RANGES` names complete
decoded functions; `CONTEXT` is search context and may contain data, not code.
Reports retain byte-range hashes. The generated `data.json` records bundle,
decompressed HUD package and language-file identities. Do not substitute
another retail revision and reuse the offsets.
The bundle SHA-256 is
`044724AB4C167831587E80F29961A1E7D8404C9DD5266533F3563C555A997299`;
English.bin is
`6CBAB64235523149B95966B1844CDCA9FB858744126F8D9AD10E72C921AB8790`.
Both are checked before decoding. `--source` identifies the caller's pinned
source commit; reports also hash the working probe/oracle files themselves.

`HUD_SingleRace.fng`. Positions below are local FEng coordinates, not a verified
absolute 1280x720 anchor. The parser bounds every `FOb`/`ObjD` enclosure and
two-byte-tag/u16-size field. `SA` has BGRA dword channels, position/depth and
size/scale. `SH` is a string hash; it is **not** evidence of a font binding.

The backing's texture/parent/material and executed blending remain separate
evidence requirements. Stored depth alone does not establish draw order, as
the independent needle correction in #253 demonstrates. The default English
text fields read `Current:`, `Best:` and `Laps`; the numeric template strings
are editor defaults, not runtime timing. Current/best and lap number use
justification field `Sj=2`; labels and total use `Sj=0`. Runtime mapping of
these flags must follow the native renderer rather than a new image fit.

The default resource binding is source-addressed: loader `0x00501887..0x005018A8`
copies the OP field's last low word into object `+0x22`.
`0x005003C0..0x00500410` uses that index with stride24 to copy resolved resource
fields `+0x10/+0x14` to object `+0x24/+0x28`. Text submit
`0x004F25F0..0x004F27CC` resolves object `+0x24` through `0x004F43D0` before
calling the glyph renderer. `Res/RsRq` contains count-prefixed 24-byte requests;
each request's `+4` points to the bounded `RsNm` filename table and `+8`
classifies fonts as type2, textures as type1.

| Fields | OP resource index | Default package request |
| --- | ---: | --- |
| CurrentLapTime, BestLapTime and both labels | 3 | ConduitMdITC_TT14i.ffn |
| LapNumber | 5 | LCD_LET48.ffn |
| NumberLaps and LapText | 0 | Font_ConduitMdITCTT38bi.ffn |
| LapCounterBacking_1 | 2 | 3rdperson_BoxCorner.tga |
| LapCounterBacking_2 and _3 | 4 | White16x16.bmp |

These are recovered **default resource requests**, not an assertion that no
later runtime override occurs. The language probe reports bounded matching
FNTF glyph records, texture names, bearings and advances.
`0x004F4790` supplies bordered glyph geometry and `0x004F48B0` advances by the
native signed glyph advance. Later font overrides, label localization,
absolute anchor/safe area and matched event0 screenshots remain unverified.

## Native consumers and formatting

Constructor `0x004A1580..0x004A181F` resolves LapNumber, NumberLaps,
BestLapTime and CurrentLapTime into component fields `+0x20..+0x2C`. It also
includes the three backing objects and static labels. Updater
`0x004A1820..0x004A1B44` reads the current view's lap record. The ordinary
event0 configuration recovered by #268 has two laps; the no-total/free-lap
branch requires mode1, configured laps zero and another zero predicate.
It cannot justify omitting the total from event0 because a reference still
shows only `1 Laps`.

- The displayed lap comes from signed **highest lap** at lap record `+9`,
  plus one, formatted `%2d`. Total comes from status `+0x530`, formatted
  `/%2d`. There is no clamp to total in the component update itself.
- Current start is record `+0x24 + 4*status[+0x53E]`. Both zero and the
  no-time sentinel select localized string hash `0x61C9B7A2`.
- A new-lap pulse `+0x0D` copies world ticks to component `+0x44` and the
  completed finish split to `+0x48`. The display retains that value while
  elapsed ticks times the native float tick constant compare at most three
  seconds; then it uses world time minus the new lap start. Rendering does
  not stop the next lap's clock.
- Best is record `+0x60 + 4*status[+0x53F]`. **Zero** selects literal
  `--:--:--`; `0x7FFFFFFF` instead reaches the common formatter and displays
  zero time. These states must not be collapsed into one invented placeholder.
- Formatter `0x00586580..0x00586639`, field splitter `0x005864F0..0x00586576`
  and field formatter `0x00586090..0x00586485` supply the actual strings.
  Flags4 preserve a leading padding space, hundredths truncate, and the
  integer at `0x006EE6F0` selects separator templates. Setting it to5 yields
  the colon/decimal style seen in the supplied English-looking still. This
  synthetic setting is not a recovered event0 option producer. The formatter
  switches to an hours layout for longer times. Existing `format_race_ticks`
  is a report formatter and must not be assumed byte-identical to this UI.

`tools/hud254_native.py` executes these pinned bytes in Unicorn. Only UI
string-binding/localization/unhide calls are captured stubs in the lap test;
the arithmetic and common formatter execute native code. `native.json`
contains synthetic start, invalid start, running, rollover, hold boundary,
zero/sentinel best, fresh retry, same paused snapshot and finished-record
cases. Their expected values belong in `hud254_trace_test.py`, not here.
Pause/retry cases establish consumer behavior for supplied records, not the
complete runtime pause or teardown producer. A finished record can increment
the displayed lap beyond the total if the updater is called in isolation;
visibility must govern presentation rather than an untraced clamp.

## Visibility and integration limits

Mask producer `0x0042E620` reads view permissions at `+0x30`.
At `0x0042E90A..0x0042E918`, permission `0x100` adds low mask `0x508`.
Component application `0x004A9540` uses low `0x400` for lap/time. Missing
view car, blocked scene/view states and early race stages return other masks;
the finish-view branch at `0x0042E739..0x0042E78E` excludes lap/time.

The native mask matrix deliberately fixes ordinary mode, single-human plus
three-rival counts and supplied view state/permission. Non-lap predicates are
explicit zero-return stubs, listed per case. It is a bounded branch proof,
**not** an exact default event0 visibility trace. The view permission and
state producers, original flyby/GO/pause/finish footage and profile option
combination remain missing. #268's research PR is the setup/state dependency.

The supplied 30 reference stills include ordinary lap/current/best panels but
do not identify event0 or show its lifecycle. Absolute placement measurements
must state the image identity and keep native scale; different aspect ratios
must not be stretched into apparent agreement.

Proposed integration, subject to coordinator approval: consume one immutable
per-actor timing snapshot after authoritative progress/timing, use highest lap
and explicit validity, and append a bounded geometry pass without changing
the gauge. Keep standings/results in #269 and map in #266. No dummy opponents,
guessed event0 mask, synthetic winner, or new timing advancement in drawing.
Validate start, rollover, finish, pause and retry plus unchanged replay state.

Remaining acceptance: approved shared-HUD base; runtime override/anchor/material
trace; event0 default visibility and full lifecycle; real event0 actors/setup;
rendered stock retail-versus-Switch comparison; independent review; owner
visual feedback and paired HUD performance. Console scheduling belongs to the
coordinator, with explicit `--scene-height 540 --gpu-boost on`, 1280x720 HUD
presentation and actual clocks recorded separately. No hardware result or
60 fps claim is made by this research.
