# Race MSAA 2x hardware comparison candidate

Owner requested MSAA 2x instead of FXAA, same resolution and reflections.
Direct root-only work. Parent: 0fa148f. Local worktree:
build/day20261008-root-combined. No source push, merge or other scope.

Build options: NFSU_RACE_MSAA2=ON, NFSU_RACE_FXAA=OFF, tag msaa-r1.
Both AA options default OFF; configuring both ON is explicitly refused.
Always set both when switching builds because CMake caches option values.

Main race scene uses two-sample RGBA8 color and ZF32 depth, both 2DMS images.
The raster state selects 2x and SDK default distinct sample locations; the sample
mask includes both samples. Existing opaque, alpha-tested, blended and effect
pipelines are retained. Alpha-to-coverage remains OFF; this does not claim to
remove all foliage, texture or specular aliasing. Six-face car captures and road
reflection targets remain single-sampled. MSAA is disabled again before HUD.

The main multisampled color/depth pair is shared across frame slots on the sole
GPU queue, as in the SDK Example06_Multisampling.cpp. CPU never writes those
images. Every frame clears them, fully completes drawing before resolve, and
completes resolve before they can be reused. Low-resolution single-sample resolve
outputs remain per slot. Resolve is at the existing scene dimensions followed
by the unchanged linear upscale. Native-resolution mode resolves to the native
presentation image. HUD is drawn only after resolve/upscale. Whole-scene GPU
timestamps include MSAA and resolve costs. No FXAA pass runs in this build.

API evidence: installed devkitPro deko3d.h/deko3d.hpp, and SDK multisampling
example. Original driver sample-location implementation inspected at:
https://github.com/devkitPro/deko3d/blob/master/source/maxwell/gpu_3d_ms.cpp
The default constructor alone has centered samples; setLocations() after
setMode(2x) selects the SDK two distinct sample positions.

Validation: actual SDK full build and Switch CTest 51/51 PASS, including NRO,
shader and existing menu/profile guards. Build cache confirms FXAA OFF/MSAA2 ON.
Only Switch-specific sources/CMake changed, so native game algorithms and
historical native-gate acceptance limits remain. No desktop rendering test is
claimed to validate the Switch resolve API. GPU-only shared targets avoid a
second duplicated multisampled pair; actual allocation remains a hardware check.
The fixed GPU budget is retained and refuses over-budget allocation.
